# Архитектура приложения GoTrain Marketplace

## Обзор

GoTrain Marketplace - это высоконагруженное веб-приложение для онлайн-маркетплейса, построенное на основе Clean Architecture с использованием языка Go. Приложение предоставляет функциональность для управления пользователями, продуктами, предложениями, корзиной, заказами, платежами и возвратами.

## Архитектурные принципы

Приложение следует принципам Clean Architecture, разделяя код на следующие слои:

1. **Delivery Layer (Слой доставки)** - HTTP handlers и роутинг
2. **Service Layer (Слой сервисов)** - Бизнес-логика и оркестрация
3. **UseCase Layer (Слой use cases)** - Специфичные бизнес-правила
4. **Repository Layer (Слой репозиториев)** - Работа с данными
5. **Domain Layer (Слой домена)** - Модели данных и бизнес-сущности

## Компоненты системы

### 1. Delivery Layer (`internal/deliveries/http/`)

Отвечает за обработку HTTP-запросов и формирование ответов. Включает:

- **Handlers**: Обработчики HTTP-запросов для каждого домена (user, product, cart, order, refund)
- **Routes**: Определение маршрутов и их регистрация
- **Middleware**: 
  - `auth.go` - JWT аутентификация
  - `logging.go` - Логирование запросов
  - `permissions.go` - Проверка прав доступа

### 2. Service Layer (`internal/services/`)

Содержит бизнес-логику и оркестрацию между различными use cases:

- **UserService**: Управление пользователями, регистрация, аутентификация
- **ProductService**: Управление продуктами
- **OfferService**: Управление предложениями продавцов
- **CartService**: Управление корзиной покупок
- **OrderService**: Обработка заказов
- **PaymentService**: Интеграция со Stripe для обработки платежей
- **RefundService**: Обработка возвратов

### 3. UseCase Layer (`internal/usecases/`)

Содержит специфичные бизнес-правила и валидацию:

- Каждый use case отвечает за конкретную бизнес-операцию
- Изолирован от деталей реализации (HTTP, база данных)
- Может использовать несколько репозиториев

### 4. Repository Layer (`internal/repositories/`)

Абстракция для работы с данными:

- **PostgreSQL репозитории**: Реализация работы с базой данных через sqlx
- Изолирует бизнес-логику от деталей работы с БД
- Все репозитории используют единое подключение к БД

### 5. Domain Layer (`pkg/domain/`)

Содержит доменные модели и бизнес-сущности:

- Модели данных (User, Product, Offer, Cart, Order, Refund, Payment)
- Бизнес-правила и валидация на уровне домена
- Не зависит от внешних библиотек

### 6. Infrastructure Layer

Внешние зависимости:

- **PostgreSQL**: Основная база данных
- **Stripe**: Сервис обработки платежей
- **JWT**: Аутентификация пользователей

## Поток данных

### Пример: Создание заказа

1. **HTTP Request** → `OrderHandler.CreateOrder()`
2. **Middleware** → Проверка JWT токена и прав доступа
3. **Service** → `OrderService.CreateOrder()` - валидация и оркестрация
4. **UseCase** → `OrderUseCase.CreateOrder()` - бизнес-логика
5. **Repository** → `OrderRepository.Create()` - сохранение в БД
6. **Payment Service** → Создание Payment Intent в Stripe
7. **Response** → Возврат данных заказа клиенту

### Пример: Webhook от Stripe

1. **HTTP Request** → `StripeWebhookHandler.HandleWebhook()`
2. **Payment Service** → Верификация подписи webhook
3. **Order Service** → Обновление статуса заказа
4. **Repository** → Сохранение изменений в БД

## Технологический стек

- **Язык**: Go 1.23.4
- **Веб-фреймворк**: Gorilla Mux
- **База данных**: PostgreSQL
- **ORM/Query Builder**: sqlx
- **Миграции**: golang-migrate
- **Аутентификация**: JWT (golang-jwt/jwt)
- **Платежи**: Stripe API
- **Валидация**: go-playground/validator
- **Логирование**: logrus
- **Документация API**: Swagger (swaggo)

## Безопасность

- JWT токены для аутентификации
- Хеширование паролей (bcrypt)
- Middleware для проверки прав доступа
- Валидация входных данных
- Верификация webhook от Stripe

## Масштабируемость

Архитектура поддерживает горизонтальное масштабирование:

- Stateless приложение (JWT токены)
- Подключение к внешней БД
- Возможность добавления кэширования (Redis)
- Возможность добавления очередей сообщений для асинхронной обработки

## Миграции базы данных

Миграции находятся в `migrations/` и управляются через `golang-migrate`:

- Версионирование схемы БД
- Откат изменений (down миграции)
- Автоматическое применение при запуске (опционально)
